# wikipedia-interest-analysis

Agent Skill, з якою агент відповідає на продуктові питання B2C-засновників («яку тему додати», «якою мовою запускатися») за даними переглядів Wikipedia. Навичка рахує тренд і довіру до нього, будує графік і формує PDF на одну сторінку.

> Статус: **v0.2 (2026-09-27)**. Повний сценарій працює на реальних даних; 11 eval-сценаріїв проганяються на обраній моделі (`--model`) по 3 рази (результати в розділі «Як перевірявся результат»).

## Встановлення та запуск

```bash
npm ci                       # один раз; Node.js ≥ 22.18 (розробка: 24 LTS, див. .nvmrc)
node scripts/wiki.ts resolve --topic "astronomy" --langs uk
node scripts/wiki.ts analyze --qids Q333 --langs uk --months 36
node scripts/wiki.ts resolve --topics "astronomy|black hole|galaxy" --langs uk,pl      # широка тема: підтеми
node scripts/wiki.ts analyze --basket "astronomy=Q333,Q589,Q318" --langs uk,pl
node scripts/wiki.ts report --run wiki-interest/<run> --title "..." --question "..." --takeaway "..."
npm run lint && npm test && npm run typecheck
node evals/run.ts [--model haiku] --repeat 3 [id ...]    # evals на обраній моделі (рахуються в ліміт підписки Claude)
```

Навичка лежить у `.claude/skills/wikipedia-interest-analysis/`, звідки Claude Code знаходить її автоматично. Щоб використати її в іншому проєкті, скопіюйте цю папку в його `.claude/skills/` (або в `~/.claude/skills/` для всіх проєктів) і виконайте `npm ci` у ній.

## Ключові рішення

| Рішення | Чому |
|---|---|
| **Код рахує всі числа, модель їх лише переказує** | Дешева модель не вигадуватиме цифр. `findings` — це вже готові речення. |
| **Перевірка відсотків у тексті звіту** | `report` відхиляє takeaway з відсотками, яких немає в аналізі (допуск ±1 п.п.). Модель отримує повідомлення про помилку й виправляє текст. |
| **Тема → стаття лише через Wikidata** | Назви статей різняться між мовами. Без спільного QID порівняння мов некоректне. |
| **Частка від трафіку розділу, а не абсолютні перегляди** | Трафік Wikipedia падає, і в деяких розділах сильно: людський трафік uk-розділу за 3 роки зменшився майже вдвічі (94 млн → 51 млн переглядів на місяць). Без нормалізації майже все виглядало б як спад. |
| **YoY за однакові місяці + Theil–Sen + Mann–Kendall** | Прибирає сезонність і стійкий до викидів. Прості методи, які можна пояснити користувачу. |
| **Довіра як набір явних «обмежувачів»** | Користувач бачить не лише рівень довіри, а й причину (`reasons`). |
| **Мало кроків, JSON-вивід, підказка «що далі» в помилках** | Розраховано на будь-яку модель, зокрема слабку й дешеву. |
| **TypeScript без збірки й без нативних залежностей** | Node ≥ 22.18 сам запускає `.ts` (стирає типи), тож tsx і крок збірки не потрібні. `npm ci` відтворюваний. Chromium і canvas не потрібні. Roboto з pdfmake підтримує кирилицю й діакритику. |
| **Кеш назавжди для завершених місяців** | Повторні й уточнювальні запити виконуються за частки секунди. |
| **Підказки в JSON-виводі, а не лише правила в SKILL.md** | Модель уважніше читає вивід команди, ніж інструкцію. «Не аналізуй до підтвердження» в SKILL.md спрацьовувало в 1 з 6 прогонів, `hint` «STOP… Do NOT run analyze» у виводі `resolve --topics` — в 6 з 6. |
| **Широкі теми — кошик підтем** | Головна стаття галузі — 3–4% інтересу до неї. Підтеми пропонує модель (автоматичний підбір з Wikidata давав біографії), користувач підтверджує, код складає і дає розбивку. |
| **Галузь чи вузьке поняття: критерій + клас Wikidata** | Модель вирішує за критерієм у SKILL.md (галузь, хобі, «вивчення X» → кошик; одна річ → стаття). Для найпоширенішого кандидата `resolve` запитує клас P31 (1.2 КБ): academic discipline, branch of science, field of study/work → `broad_field` і hint «одразу `resolve --topics`, спитай один раз». Клас hobby не враховується, бо його мають і шахи. |
| **Рейтинг рахує зростання лише для підтверджених напрямів** | `flat` (+1.5%) і `unclear` (один обвал) отримують 0 балів за зростання, інакше рейтинг підштовхував модель до «це єдиний ринок, що росте». |

## Що знайшлося на реальних даних (і вже враховано)

- **Відсутні статті:** «інтервальне голодування» не має статті в plwiki, тож приклад 1 із завдання одразу впирається в прогалину контенту. Навичка повідомляє про це, а команда `search` допомагає знайти замінник.
- **«Вивчення англійської»** не має відповідника в кожній мові: ESL-статті немає в pl та uk. «Англійська мова» (Q1860) є скрізь, тому SKILL.md вчить явно обирати й називати тему-замінник.
- **Сезонність:** астрономія має пік щовересня (шкільна програма), дієти — у січні. Перша версія детектора зсуву рівня сприймала літній провал за зсув; тепер повторення через 12 місяців вважається сезонністю (є тест).
- **Різкі зсуви рівня:** uk «Інтервальне голодування» впало приблизно в 4 рази в середині 2025 року. Навичка позначає це як підставу перевірити причину, а не як «падіння інтересу».
- **Одна стаття ≠ інтерес до галузі:** у кошику з 11 підтем астрономії головна стаття «Астрономія» дає лише 3–4% переглядів. uk-кошик `declining` (−34%) з високою впевненістю, тоді як одна стаття давала `unclear`. У pl кошик загалом `flat`, і тримає його «Сонячне затемнення» (+45%).

## Як перевірявся результат (AI-асистований код)

1. Unit-тести на синтетичних рядах із відомою відповіддю: нахил, значущість, сплеск, ступінчастий зсув, сезонність, рейтинг, перевірка чисел.
2. Звірка з першоджерелом: місячні суми для uk «Інтервальне голодування» зі звичайного API (`monthly`) збіглися з агрегацією коду з денних даних до одиниці (−76.1% YoY, 175 переглядів/міс.). Далі варто також звірити з https://pageviews.wmcloud.org.
3. Візуальна перевірка PDF: одна сторінка, кирилиця й чеська діакритика відображаються правильно.
4. `tsc --noEmit` у strict-режимі.
5. **Evals** (`evals/run.ts`, 11 сценаріїв × 3 повтори). Кожен прогін іде в окремій порожній папці з лише цим скілом і без auto-memory розробника: перші прогони в папці проєкту бачили нотатки розробника і результати сусідніх прогонів, і це змінювало поведінку. Модель недетермінована, тож кейс оцінюється за часткою успішних повторів. Результати нижче отримано з `--model haiku`; на іншій моделі їх треба перепрогнати.

| Сценарій | Головне очікування | Відомі відхилення |
|---|---|---|
| ambiguous-topic (Меркурій) | 3/3 питає значення з QID | — |
| disambiguated-topic | 3/3 Q308 без питання | 2/3 вгадують причину сезонності чи спаду |

## Обмеження

Перегляди означають цікавість, а не готовність платити. Мовний розділ ≠ країна. Боти частково просочуються в `user`. Перегляди редиректів не враховуються. Спад евергрін-статей частково спричинений тим, що пошукові системи й AI відповідають на запити самі. Звіт поки лише англійською (крім тексту takeaway). Модель іноді: називає `flat` з додатним відсотком зростанням, вгадує причини (школа, новини, AI-пошук як факт), пише країну замість мовної версії, вставляє російські слова. Правила проти цього є в SKILL.md і у виводі коду; далі це межа моделі.

### Помилки в SKILL.md (огляд 2026-09-26)

Найбільше впливають на якість відповіді пункти 2, 3, 4 і 6.

*Підтверджені прогонами eval:*
1. ✅ **`npm ci`** (2026-09-27). «First run only» модель перевірити не може, тому запускала `npm ci` про всяк випадок (4 з 7 прогонів). Блок прибрано з SKILL.md: при відсутніх залежностях `wiki.ts` сам повертає помилку з точною командою в `fix`. Перевірити в наступних evals, що модель виконує саме `fix`, а не власний `npm install`.
2. ✅ **Частка vs загальне падіння трафіку** (2026-09-27). Модель пояснювала падіння частки загальним падінням трафіку Wikipedia, хоча частка його вже прибирає. У SKILL.md додано пряму заборону, а gotcha про евергрін-статті переписано як гіпотезу («likely», «possible factor»). Відрізнити ефект типу статті від втрати інтересу до теми можна лише контрольною групою (Roadmap, п. 4).
3. ✅ **Вигадані причини** (2026-09-27). У SKILL.md є загальне правило: дані показують що, а не чому; причину можна назвати лише як гіпотезу для перевірки. Gotcha про сезонність більше не підказує «school subjects». Код рахує `signals` (будні/вихідні відносно розділу, чи спільний сплеск і місяць піку з іншими мовами), на які модель може спиратися. Перевірити в evals, що модель не пише «школярі» як факт.
4. ✅ **Конфлікт правил** (2026-09-27). «Кажи "спадає", якщо так каже `direction`» vs «при зсуві рівня тренд не підтверджений» (астрономія uk: модель написала і «знижується», і «це технічний артефакт»). Тепер вирішує код: зсув рівня в останніх 24 місяцях → `direction: unclear` з поясненням у `findings`. У SKILL.md одне узгоджене правило: `unclear` = немає надійного напряму, навіть якщо відсоток великий.
5. ✅ **Мова відповіді** (2026-09-27). Було лише «Translate the headings», а в українських відповідях траплялися російські слова («вероятно», «ищуть»). Тепер правило: усе, що бачить користувач (зокрема уточнювальні питання й перекладені `findings`/`reasons`/`signals`), пишеться мовою питання, без змішування мов. PDF поки що англійською, крім takeaway (Roadmap, п. 5).

*Знайдені при перечитуванні:*
6. ✅ **Шаблон на один ряд** (2026-09-27). Шаблон був розрахований на одну серію, тому модель зводила кілька мов до одного висновку («падає в обох»). Тепер Short answer і «Why confidence is not high» пишуться для кожної серії, у таблиці є колонка `Direction`, а узагальнювати можна лише при однаковому `direction` в усіх серіях.
7. ✅ **Словник для `flat` / `unclear`** (2026-09-27). У Interpretation rules: `flat` → «no significant change», `unclear` → «no reliable direction»; заборонено «stable interest» і «slightly declining».
8. ✅ **Відсутня стаття** (2026-09-27). Крок 3 казав питати, а Resolve і Gotchas — продовжувати. Тепер одне правило (блок «Missing articles»): не зупинятися, спробувати `search`; точну статтю під іншою назвою аналізувати через `--articles`; неточний замінник ніколи не додавати в основний аналіз, а лише пропонувати окремо як proxy; питати лише коли статті немає в жодній мові.
9. ✅ **Порядок правил** (2026-09-27). «Pick the candidate» стояло перед блоком «не вибирай, питай», тож модель могла вибрати одразу. Тепер одне правило «Choosing the candidate»: прочитати описи → відкинути нерелевантних → один кандидат = використати, два й більше = спитати.
10. ✅ **Папка запуску** (2026-09-27). `run_dir` створюється відносно поточної папки, тож модель, що робила `cd` у скіл, писала результати всередину скіла. Тепер `analyze` без `--out` відмовляється працювати зсередини папки скіла й повертає `error` + `fix` («cd у папку проєкту»); у SKILL.md додано правило не робити `cd` у `SKILL_DIR`.
11. ✅ **Node у frontmatter** (2026-09-27). Мінімум піднято до 22.18+ (SKILL.md, `engines`, README): Node 20 більше не підтримується, а залежності вимагали 20.19+. Для розробки — Node 24 LTS через `.nvmrc` у корені проєкту.
12. ✅ **«Usually a rename»** (2026-09-27). Gotcha про зсув рівня сам стверджував неперевірену причину («usually a rename… not a real change in interest»). Тепер реальна зміна інтересу стоїть поруч із технічними причинами: «the data cannot tell them apart».

Автоматичний підбір з Wikidata давав переважно біографії (Ньютон, Галілей), тож підтеми пропонує модель, код знаходить їх у Wikidata (`resolve --topics`), користувач підтверджує, а `analyze --basket` рахує суму й розбивку по підтемах. Ще не зроблено: розбивка в PDF, «повний» кошик для однієї мови поруч зі спільним, контрольна група (п. 4) поверх кошиків.
3. Підсумовування переглядів редиректів і автоматичне виявлення перейменувань (`list=logevents`) замість лише попередження.
4. **Контрольна група** (пріоритетний геп): порівняння теми з кошиком схожих статей того ж розділу (той самий клас чи галузь у Wikidata). Якщо тема падає так само, як кошик, це ефект типу статті (AI-пошук), а не втрата інтересу. Якщо падає сильніше, інтерес до теми справді зменшився. Класифікація «евергрін / ні» цього не замінює: майже всі теми користувачів евергрін, а межа розмита.
5. Локалізований звіт (uk/en) і шаблони для різних типів питань (тема vs мова vs порівняння тем).
